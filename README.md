## 📖 项目简介

**shso** 是一款运行在 Android ROOT 环境下的图形化辅助执行工具（包名 `com.mixradio.droid`，`versionName = Jinn`，`versionCode` = 构建当日日期如 `20260911`）。

在日常玩机、系统调优或模块调试过程中，经常需要运行 Shell 脚本（`.sh`）或原生可执行程序（`.so` / ELF 二进制）。shso 把这一流程图形化：无需面对复杂命令行即可一键执行脚本、实时查看带 ANSI 颜色高亮的控制台日志、进行标准输入交互，并在手机上完成全盘 ROOT 级别的文件管理、文本编辑/对比、压缩包解压与 APK 安装。界面为等宽字体 + 直角矩形玻璃暗色风格，冷启动直接进入主页四 Tab（主页 / 终端 / 文件 / 设置），无多余加载流程。

> **权限模型（核心原则）**：普通用户本就能用的功能（浏览文件列表、删除 / 拷贝 / 重命名、文本编辑、解压、安装 APK、书签等）**不强制依赖 ROOT**；仅当设备授权 ROOT 时，**优先使用 ROOT 权限**（可覆盖受保护 / 系统路径），其余情况回退普通文件权限（`java.io.File`）。`/data/adb/shso` 工作区写入属天然 ROOT 专属路径。

## 1. 🚀 主页（Home）

- **路径执行**：直接输入文件绝对路径，或点击「从文件管理器选择」调起内置选择器。
- **格式限制**：仅允许执行 `.sh` 脚本与 `.so` 二进制程序，其余格式明确拒绝并提示。
- **立即执行**：校验通过后调用执行引擎，自动跳转终端页展示实时日志；任务运行中可「点击覆盖启动」。
- **shso 目录文件**：内置展示 `/data/adb/shso` 工作区文件（图标区分 文件夹 / SH / SO / 普通文件），点击选中、按钮「选择」，支持上级返回与刷新；字号跟随全局文件列表设置。

## 2. 💻 终端（Terminal）

- **ANSI 文本着色**：内置 ANSI 转义序列解析器，支持标准 16 色与加粗渲染；文字颜色可在终端设置中通过色轮自定义（彩虹色相条 + 明暗条 + 16 个预设色）。
- **中文状态灯**：左上角状态点 + 文字——空闲为绿「待命中」，运行中为红「运行中」并带循环点（`.` `..` `...` `....` `.....` 每 400ms 递增）。
- **紧凑操作区**：顶部一排裸文字按钮——`复制输出` / `结束进程`（运行中才可点）/ `重启终端` / `设置`。
- **输入与交互**：底部「请输入命令…」输入行 + `中断`（SIGINT）/ `清屏` / `Enter`（发送空行）/ `发送`（发送 stdin）。
- **终端设置随页而至**：文字颜色（色轮）、终端字体大小（5–30sp 滑杆）、`HyperCore 终端提示` 开关、`shso 终端提示` 开关。
- **智能滚动**：仅在用户已停在底部时自动跟随新日志，向上回看时不被拽回。
- **输出上限保护**：滑动窗口截断（上限 25 万字符），防止超长日志 OOM。

## 3. 📁 文件管理（File）

### 3.1 浏览与导航
 - **默认工作区**：内置快捷直达 `/data/adb/shso`（历史遗留的 `/data/adb/shso` 不迁移、不删除）。
- **全盘访问**：浏览系统根目录 `/`、内部存储、受保护 `/data` 分区（ROOT 时）。
- **顶栏六等分**：`返回 | data | storage | shso | ⭐书签 | 设置`。
- **记忆操作路径**：开关（默认开）记忆上次浏览目录，关闭则恒回 `/storage/emulated/0`。

### 3.2 列表设置（文件列表设置弹窗）
- **入口**：文件页右上角「设置」齿轮。
- **字号**：一行布局 `字号 ---拖动条--- 15 sp`（左侧标签 + 拖动条 + 右侧当前数值），5–30sp 调节（默认 15sp），与主页 shso 目录列表共用。
- **隐藏文件**：开关显示以 `.` 开头的隐藏条目。
- **排序**：`名称↓` / `名称↑` / `时间↑` / `时间↓` 四个**纯文本**选项（无圆角矩形底色容器），选中项以 Accent 色 + SemiBold 区分。

### 3.2.1 全选文件 / 取消全选
- **位置**：弹窗底部，与「新建文件」**同一行**（左「全选文件」、右「新建文件」）。
- **只选文件**：仅选中当前目录下的**文件**，文件夹不参与选中、也不计入批量操作。
- **切换语义**：
  - 第一次点击 → 全选当前目录所有文件，进入多选模式，提示「已全选 N 个文件（不含文件夹）」；
  - 已处于全选状态时再点击 → 取消全选（清空选择并退出多选模式），提示「已取消全选（N 个文件）」；
  - 弹窗文案随状态切换为「全选文件」/「取消全选」。
- **无文件**：当前目录没有文件时提示「当前目录没有可全选的文件」。
- **文件选择器入口**（如「添加到 shso」的选文件场景）不支持多选，不渲染该项。

### 3.2.2 提取 APK（设置弹窗内）

- **入口**：文件页右上角「设置」→「提取APK」。
- **作用**：从手机**已安装的应用**里导出安装包，自动放到内部存储 `Download/`。
- **命名规则**（后缀固定为**大写** `.APK`）：
  - 基础包：`<应用名>-<版本号>.APK`，例如 `微信-1234.APK`
  - 分包应用（App Bundle 上架，现已是主流）：基础包仍用上述名字，分包追加为
    `<应用名>-<版本号>-split1.APK`、`-split2.APK` …（只导出基础包通常装不上，故一并导出）
- **应用名净化**：名称中的 `/ \ : * ? " < > |` 与控制字符一律替换为 `_`，首尾空白与 `.` 去除。
- **默认范围**：只列**用户应用**，顶部「含系统应用」开关可切换（系统应用数量多、列表较长）。
- **权限要求**：应用私有安装包位于 `/data/app/...`，**读取需要 ROOT**；无 ROOT 时仅系统分区上本身可直读的应用能提取，失败会明确提示。
- **提取后**：弹 Toast 与弹窗内状态行给出结果，并通知媒体库刷新；若当前正浏览 `Download` 目录会自动刷新出来。

### 3.3 单文件动作（文件单击 / 文件夹长按弹菜单）
- `添加到shso`、`安装 APK/XAPK`（可安装时）、`浏览图片`（图片文件）、`编辑文本`（文本文件）、`重命名`、`拷贝`、`移动文件`、`删除`。
- **重命名 / 拷贝** 自动过滤 `..` `\` `\0` 等非法字符；拷贝生成同级 `_n` 递增副本。
- 移动文件夹或文件时使用内置目录选择器；普通 `java.io.File` 操作优先，失败且 ROOT 已授权时才使用 `su mv`。

### 3.4 多选批量
- 长按非文件夹文件 → 「进入多选模式」；多选模式下**单击切换选中**（仅文件，文件夹不参与）。
- 已选中后长按 → 「退出多选模式」或「批量操作（已选 N 项）」菜单。
- 批量操作：对全部选中项 **删除 / 拷贝（`_n` 副本）/ 重命名（统一名称 + `_n` 保留原扩展名）/ 移动文件**，完成后自动退出多选。
- 移动目标通过内置目录选择器确认；无冲突时直接移动。遇到同名项目时可选择 **覆盖替换 / 自动改名（目标名插入 `_new`）/ 同名不动（跳过该项）/ 直接退出**。
- 「退出多选模式」会清空当前选中项并回到普通浏览；移动完成或放弃移动后也会自动退出多选。

### 3.5 三悬浮导航按钮
- 列表右下悬浮 `⤒`（回到顶部）/ `⤓`（直达底部）/ `⟳`（刷新列表），靠右距 50dp、位于可能的「执行」按钮左侧，样式为极光渐变透明图标。
- 布局铁律（已锁定，不再改动）：列表外层 `Box` 仅预留 DockBar 高度（`weight(1f).fillMaxWidth().padding(bottom = 56.dp)`），列表底端恰好止于底部导航上沿，透明导航栏下方只显示极光背景、不穿透文件列表。

### 3.6 APK / XAPK 安装
- **ROOT 已授权**：静默安装——单 APK 先 `cp` 到 `/data/local/tmp` 再 `pm install -r -d -t`；XAPK / split 分片走 `pm install-create/write/commit` 会话流，OBB 落位 `/sdcard/Android/obb/<包名>/`。
- **无 ROOT**：回退系统安装器（FileProvider + `ACTION_VIEW`），由用户交互完成；受保护路径（如 `/data/adb`）非 ROOT 不可读时给出明确提示。
- 兼容伪装名（如 `qq.apk.1`、大小写变体）。

#### 3.6.1 分包应用自动整套安装

单文件 `pm install` 对**分包应用**（App Bundle 上架，现已是主流）必定失败（`INSTALL_FAILED_MISSING_SPLIT`），必须走会话安装。因此安装前会先在同目录里把「同一套安装包」聚齐：

- **主判定：命名约定**（无需读取文件内容）——基础包 `<名>-<版本>.APK`、分包 `<名>-<版本>-split<序号>.APK`。
  这套命名正是「提取 APK」的输出，因此提取出来的分包**可以直接安装**。
- **次判定：manifest 分组**——命名不规范时（如 SAI / MT 解包出的 `split_config.*.apk`），改用 `getPackageArchiveInfo()` 按「同包名 + 同版本号」聚合，并要求基础包能唯一定位（splitNames 为空且名字不像分包）。
- **点基础包或点任意分包，效果相同**，都会装整套。
- **不确定就退回单文件**：目录里存在两份同包同版本的基础包、或定位不到基础包时，不做猜测。
- 真机实测：`WhatsApp-263507522.APK` + 3 个 `-splitN.APK` → 安装后 `pm path` 返回 base + `split_config.armeabi_v7a` + `split_config.xhdpi` + `split_i18n_ko`，4 个分片全部就位。
- **无 ROOT 时**：识别出是分包套件会直接给出明确提示（会话安装需要 ROOT），而不是把基础包丢给系统安装器后报一个看不懂的错误。

### 3.7 图片浏览
- 点击图片文件（jpg/jpeg/png/bmp/gif/webp/ico/tiff/tif）→ 全屏查看器：右下角 `←` 上一张 / `→` 下一张 / `↻` 顺时针旋转 90°；支持双指缩放与拖动平移。

### 3.8 字体预览与应用
- 点击 `.ttf` / `.otf` 字体文件 → 预览对话框，可「应用为软件字体」设为全局等宽字体（自定义字体设置持久化）。

### 3.9 新建文件（设置菜单子项）
- **入口**：文件页右上角「设置」齿轮 → 菜单底部纯文本子项「新建文件」（Accent 色，无矩形底色，符合弹窗紧凑风格）。
- **对话框**：点击弹出「新建文件」对话框，两个并排输入框——
  - 左「文件名」：预填**今天日期到毫秒的纯数字**（如 `20260905200050166`，17 位 `yyyyMMddHHmmssSSS`）；
  - 右「扩展名」：预填 `txt`；
  - 点「创建」在当前目录生成 `<名称>.<扩展名>` 空文件后关闭并刷新列表。
- 校验：同名冲突 / 非法字符（`..` `\` `\0` 等）拦截；ROOT 授权优先 `su touch`，无 ROOT 回退 `java.io.File.createNewFile()`。

### 3.10 后台长任务
- 执行 `.sh` / `.so` 脚本或原生程序后，任务由 `RootService` 管理，并启动 `ExecutionForegroundService` 作为 Android 前台服务哨兵。
- 切换到后台后，脚本、下载或编译任务继续运行；通知栏显示任务名、耗时、PID 和 Root 状态，并提供「结束进程」操作。
- 任务结束后前台服务自动停止；服务本身不替代 `RootService`，实际 Process、stdin、日志、取消和退出状态仍由 `RootService` 负责。
- 服务使用 `dataSync` 类型和低重要性通知渠道 `shso_task_keepalive`。部分 Android 13+ 系统可能需要允许通知权限，电池优化豁免仍建议在设置页开启。

## 4. 📝 文本编辑器

> 入口：文件页「编辑文本」动作，或从主页 / 选择器打开文本文件。

- **基础能力**：打开 / 编辑 / 保存 / 另存为 / 新建；未保存时标题显示 `●` 并在关闭前提醒；自动保存草稿（间隔秒数可配，0 = 关闭）。
- **大文件分段只读**：**超过 128KB** 走 `LazyColumn` 只读分段加载（可点「加载更多」续读），禁止编辑保存以防数据截断；128KB 以内全量可编辑。
  > 阈值按低端机实测定为 128KB：Compose 的编辑框会对**整段**文本做全量排版，实测 256KB 需约 30 秒、2MB 数分钟无响应（表现为「一直空白、0 行 0 字节」）。因此宁可让大文件走只读懒加载，也不给一个假死的编辑器。
- **行号**：可开关，与编辑区共享滚动状态纵向同步。
- **字号**：8–32sp 可调。
- **编码**：自动检测（BOM → UTF-8 严格校验 → GB18030 中文兜底 → ISO-8859-1），可手动切换 UTF-8 / UTF-16 LE / UTF-16 BE / GBK / GB2312 / GB18030 / ISO-8859-1 / ASCII，保存时按需写 BOM。
- **换行风格**：自动识别并保留 LF / CRLF / CR，保存时按指定风格统一。
- **查找 / 替换**：查找下一个（光标位置环绕查找）、替换当前、全部替换。
- **编辑历史**：每文件最多 20 条（内容级去重，类 git 无变更不入库），可在「历史」中回看。
- **全文统计**：字符数、行数、纯英文数、纯中文数、纯数字数、字节数、最长行；仅在打开设置面板时计算一次（非实时重算）。
- **右侧细滚动条**：贴右缘 6dp 细条，拖动跳行并实时显示目标行号（大小 / 小文件通用）。
- **工具栏**：查找 / 对比 / 历史（带计数）/ 保存 / 设置。

## 5. 🔍 文本对比

入口：编辑器「对比」→ 选择 2 号对比文件（同后缀过滤、排除自身）→ 选择模式 → 执行（带进度与取消）。

- **逐行对比**：按行号一一对应，仅输出**内容相同的行**，格式 `[行号]\t内容`；不相同的全部排除。
- **重复对比**：忽略行号，输出两文件**共同行**（去重，纯文本，按最小行号排序）。
- **大文件优化**：内存映射（mmap）零拷贝读取，ROOT 不可直读文件先 `cat` 到临时文件；10 万行级性能；结果文件命名 `文本对比_YYYYMMDD_n<原扩展名>`。

## 6. 🗜️ 压缩包解压

- **支持 14 种格式**：归档型 `zip / 7z / tar / tgz / tar.gz / tar.xz / tar.zst / tar.bz2 / tar.lz4`；单文件压缩型 `gz / xz / bz2 / zst / lz4`（直接解压为去后缀原文件名）。**RAR 为专有商业格式，不支持**。
- **智能解压**：
  - 条件 A：根目录仅 1 个顶层文件夹 → 直接将其解压到当前目录（剥离顶层前缀，避免 `abc/abc` 嵌套）。
  - 条件 B：否则新建「压缩包名（去后缀）」文件夹容纳全部内容。
- **加密包**：zip（ZipCrypto + WinZip AES，UTF-8 中文密码）与 7z 加密时返回需密码状态，UI 弹窗收集密码后重试。
- **边界处理**：重名冲突自动追加 `_1` `_2`…；剥离 `../` 路径穿越；清理解压失败遗留空目录。
- **安全**：防 Zip Slip —— 先做词法剥离（绝对路径 / `../` / 行内 `..` 段），再对落盘路径做 `canonicalFile` 二次校验（可解析符号链接），越界即丢弃目录部分只保留文件名。
- **不可写目录保护**：目标父目录不可写时（典型如受 SELinux 限制的 ROOT 目录，即便 `chmod 777` 应用也写不进去），解压入口会**禁用并标注「当前目录不可写」**，避免点下去毫无反应。

## 7. ⭐ 书签

- 永久存储于 `SharedPreferences`（`bookmarks`，`LinkedHashSet` 保序），跨进程 / 重启存活。
- 弹窗三段式：标题 + 可滚动书签列表（纯文本贴边，点击跳转、✕ 删除）+ 底部「添加书签」（收藏当前目录）。

## 🛡️ 安全与防护说明

**通用防护**

- **防 Shell 命令注入**：所有通过 `su -c` 调用的路径均采用标准单引号转义处理（`replace("'", "'\\''")`）。
- **防路径穿越**：文件管理与重命名严格过滤 `..`、`\`、`\0` 等异常路径字符。
- **防 Zip Slip**：解压落盘路径先词法剥离、再 `canonicalFile` 二次校验（可解析符号链接），越界即丢弃目录部分。
- **进程回收**：中断（SIGINT）与「结束进程」均按**进程组**发信号，避免 `su` 之下的子进程逃逸成孤儿持续占用 CPU。
- **授权超时熔断**：ROOT 鉴权检测使用带真正超时（`waitFor(timeout)` + 强制回收）的实现，避免授权管理器卡死导致挂起或泄漏 `su` 进程。
- **滑动窗口防 OOM**：终端输出上限 25 万字符自动截断；编码探测走有界流式读取，超大文件不再整读入内存。
- **安全数据保护**：关闭 `allowBackup`，防止通过 ADB 备份机制提取私有数据。

**安全档位 0–3**（`设置 → 安全档位`，点击循环）

| 档位 | 行为 |
|---|---|
| 0 无防护 | 不拦截、不审计（行为同旧版） |
| 1 仅审计 | 不拦截，用户动作落审计日志 |
| 2 标准防护（默认） | 硬规则拦截 + 高危弹窗确认 + 脚本扫描 + 运行时守卫 |
| 3 最强防护 | 标准防护 + 脚本默认非 Root 执行 + CRITICAL 需输入 `EXECUTE` |

**静态审查（App 侧，命令解析后逐条判定）**

- **解析层**：词法切分 → 拆原子命令 → 递归展开 `$(...)` / 反引号 / `sh -c` / `eval`；剥离 `busybox`/`toybox`/`env`/`nohup`/`timeout`/`stdbuf`/`sudo`/`xargs` 等前缀（含其**带值选项**，如 `timeout 5`、`sudo -u root`）；提取 shell **重定向目标**；对残留变量与「程序名含变量」按 fail-closed 处理。
- **加密 / 混淆脚本**：`base64|xxd -r|gunzip|zcat…` 管道进 shell、`eval` 接解码器或变量、解释器内联解码载荷（`python -c "…b64decode…"`）、超长纯 base64 单行、含 NUL 的二进制内容 —— 命中即拦。
- **格机原语**：`sgdisk/parted/fdisk/sfdisk/gdisk/cgdisk/wipefs/flash_image/mtd/nandwrite`、`mkfs.*`、`wipe`、`dd` 写块设备、`truncate`/`tee` 写系统或设备、`chmod -R` 放宽系统权限、`cp/mv/install` 写入系统路径、重定向写 `/dev/block` 或 `/proc/sysrq-trigger`。
- **分级按来源**：**脚本文件**中出现 → `CRITICAL`（自动执行链路直接拒绝）；**终端手输** → `DANGEROUS`（弹窗逐项确认后仍可执行），避免误伤正常使用。
- **fail-closed 兜底**：解析超限（单行 >32KB / 原子数超限）、脚本 >2MB 无法完整扫描、内容疑似加密 —— 未经用户确认的自动执行一律拒绝。

**运行时守卫（`module/shso_guard`，档位 ≥2）**

- 随 APK 以 `assets/shso_guard.zip` 分发，安装到 `/data/adb/modules/shso_guard`，通过 **PATH 前置**拦截破坏性命令并落审计日志 `/data/adb/shso/audit.log`。
- 覆盖包装器：`rm/rmdir/shred/truncate/wipe/dd/fastboot/mkfs*/mke2fs/make_f2fs/mv/cp/find/sed/toybox/busybox`，以及 v1.2.0 新增的 `chmod/chown/chgrp/mkfs/mknod/sgdisk/parted/fdisk/flash_image`。
- 策略文件 `/data/adb/shso_guard/policy.conf` 可编辑（`protect=` / `allow=` / `mode=enforce|log|off`），修改即时生效；`mode` 会按当前档位自动同步。
- 安装/升级为**原子替换**：同文件系统内构建 `.new` → 校验 → 旧目录挪 `.old` → `mv` 替换 → 清理；任一步失败保留或回滚旧版本。
- **能力边界**：PATH 前置型守卫无法拦到脚本内部的**绝对路径**调用（如 `/system/bin/rm`）或自行重置 `PATH` 的情况；这类绕过由 App 侧静态审查覆盖（App 解析并执行的命令），但脚本内部自行拼装的绝对路径调用不在其内。

### 🔄 版本号规则与检查更新

- **版本命名（2026-09-11 起生效）**：
  - `versionCode` = **构建当日日期**纯数字（`YYYYMMDD`，例如 `20260911`），是「是否有新版」的唯一判定依据；
  - `versionName` = **`Jinn`**（固定字符串，仅作展示，不再使用 `9.0.2` 之类的数字版本名）。
  - GitHub 发布标签同样采用**纯日期**格式（如 `20260911`），与 `versionCode` 天然对齐。
- **检查更新（设置页）**：设置页底部「检查 github 是否发布了新的版本」一项，点击后应用会抓取 `https://github.com/yezijinn/shso/tags`，正则提取其中的纯数字标签（兼容 `v20260904` 与 `20260904` 两种写法），取最大值与本地 `versionCode` 做大小比较：
  - 远端更新 → 显示「发现新版本：\<tag\>」+「去更新」按钮（跳转 `https://github.com/yezijinn/shso/releases`）；
  - 已是最新 → 显示「已是最新版本 无需更新」；
  - 网络异常 → 弹框提示「网络不佳 建议开启科学上网」。
- **作者发布纯日期版本**：仓库 `Actions` 中另提供「发布 Release（纯日期标签）」工作流（手动触发），自动以当日日期打标签并上传 APK；留空则取构建当日，亦可在表单中手动指定 `YYYYMMDD` 标签。
