# 规范

文档写作、文档职责与代码命名三部分约定。与 Kotlin 官方规范一致处不再解释原因，只列本工程的强制项与豁免项。

## 一、文档写作

1. **结论先行**：章节首句给结论，再给依据。禁止铺垫、悬念、设问。
2. **陈述句为主**：用「应为 / 实测为 / 约束为」，不用「我们」「大家」「其实」。
3. **零修饰**：禁 emoji、感叹号、加粗堆砌、营销口吻。
4. **不写过程叙事**：只保留结论、原因、证据。过程属 git 历史。
5. **数据须有出处**：数值标注来源（真机型号 / 单测任务 / commit），无出处的估计值不写。
6. **术语一致**：同一概念全文同一写法；技术术语保留英文原文。
7. **中英混排空格**：中文与英文、数字之间加空格。

| 项 | 规则 |
|---|---|
| 标题层级 | 最多三级；一级标题每文件仅一个 |
| 列表 | 一行一条，同级结构平行 |
| 表格 | 多维对比、参数清单、映射关系一律用表格 |
| 代码与路径 | 反引号包裹，代码块带语言标注 |
| 日期 | `YYYY-MM-DD` |
| 状态标记 | `[ ]` 待办 / `[/]` 进行中 / `[x]` 完成 / `[!]` 阻塞 |
| 引用 | 路径用相对链接，跨目录写明源位置 |

## 二、文档职责

| 文档 | 写 | 不写 |
|---|---|---|
| `README.md` | 功能、环境、构建、执行方式、版本规则、在线编译 | 更新日志、实现细节 |
| `更新日志.md` | 变更清单，一行一条，日期倒序 | 实现细节、过程 |
| `docs/PROJECT.md` | 技术栈、架构、执行方式、构建约束、已知注意点 | 重复 README 的功能清单 |
| `docs/规范.md` | 本文档：写作准则、职责边界、命名约定 | 功能与架构 |
| `TASKS.md` | 当前状态、最近轮次、遗留风险、缺陷台账 | 已归档的历史过程 |

维护流程：改动功能后 代码 → 单测 → `更新日志.md` → `README.md` / `PROJECT.md`（仅当影响用法或约束）→ 提交。

历史轮次明细由 git 历史承担；文档只保留现行结论，不随会话增长。

## 三、代码命名

| 元素 | 风格 | 示例 |
|---|---|---|
| 包 | 全小写，无下划线 | `com.mixradio.droid.data` |
| 类 / 接口 / 对象 / 注解 | PascalCase | `RootService`、`AnsiParser` |
| 函数 / 属性 / 局部变量 | camelCase，动词开头 | `listFiles`、`resolveTargetPath` |
| `const val` 与顶层不可变集合 | UPPER_SNAKE | `MAX_LOG_LENGTH`、`TEXT_EXTENSIONS` |
| 主题令牌 | PascalCase（例外） | `AuroraTokens`、`AuroraShapes` |
| 类型参数 | 单个大写字母 | `T`、`R` |
| 测试函数 | 反引号 + 中文陈述句 | `` fun `stat 空值或非正值回退为 0`() `` |

**主题令牌例外**：`Aurora*` 为设计令牌对象，按对象而非常量命名；新增令牌沿用该前缀。

### Compose

- 无返回值的 `@Composable` 用 PascalCase 名词：`DockBar`、`SettingsPage`。
- 带返回值或返回 `Modifier` 的用 camelCase：`auroraGlass(...)`。
- 状态提升参数用 `value` / `onXxxChange`；事件回调用 `onXxx`，不用 `xxxListener`。

### 布尔与常量

- 布尔用 `is` / `has` / `can` / `should` / `use` / `show` / `auto` 前缀，禁止裸 `flag`。
- 时间量带单位后缀：`*Ms` / `*Sec` / `*Nanos`，同类不得混用。
- 阈值常量体现含义：`LARGE_FILE_THRESHOLD`，不写 `LIMIT` / `MAX_SIZE`。
- 单位写进名字：`backlogChars`、`minIntervalMs`。

### 项目词汇表

| 概念 | 命名 | 禁用 |
|---|---|---|
| 是否以 ROOT 执行 | `runAsRoot`（跨层参数）/ `useRoot`（局部开关） | `root`、`isRooted`、`asRoot` |
| 横幅开关 | `showHyperCoreBanner` / `showShsoBanner` | `showBanner`、`showHyperCore` |
| 路径 | `path`（文件绝对路径）、`dirPath`（目录）、`name`（文件名） | `filePath` 与 `path` 混用 |
| 品牌 | 包名与文案用 `shso`；类名前缀 `Shso` | `KernelEX`（历史名） |

### 禁止项

- 标识符不用下划线（测试函数名与 `const val` 除外）。
- 缩写词大小写统一：写 `Apk` / `apk`；已定型缩写（ANSI / SELinux / OBB）按既有写法。
- 不用匈牙利前缀（`mPath`、`strName`）。
- 业务语义变量禁单字母：用 `ch` / `file` / `result` / `path`。豁免：`i` / `j` 索引、lambda 的 `it`、坐标 `x` / `y` / `w` / `h`、时间分量 `h` / `m` / `s`、长度 `n`。
