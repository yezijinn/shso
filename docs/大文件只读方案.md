# 大文件只读方案

结论：shso 的「超大文件只读浏览」采用稀疏字节偏移索引 + 256KB 块缓存 + 虚拟滚动 + 体积分档，方案对齐 MP-Manager 项目解析文档；与 MP-Manager 的差异仅在三处，均为 shso 渲染通道与编码支持所致。

相关：[`docs/PROJECT.md`](PROJECT.md)（架构与约束）。

## 1 方案来源

| 文档（`项目解析文档/`） | 取用章节 | 内容 |
|---|---|---|
| `Kotlin高性能文本编辑器实现指南.md` | §4.3 | 稀疏字节偏移索引，`granularity = 1024`，查询第 N 行最多扫 1024 行 |
| 同上 | §9.1 / §9.2 / §9.3 | `FileSizeClass` 四档；`ChunkedDocument` 256KB + `LruCache(16)`；只读预览用虚拟列表 |
| `大体积文档编辑功能Kotlin移植可行性分析.md` | §6.2 | `FileSizeClass` 四档阈值（5 / 50 / 200 MB） |
| 同上 | §7.1 / §7.2 / §7.3 | 三模式分派；`ChunkedDocument` 256KB + 块缓存；行偏移索引 |
| `文档打开与编辑模块详解.md` | §6.1–§6.3、§11 | MP-Manager 现状：编辑器**无**分块加载，列为可改进点，建议 `RandomAccessFile` + 行索引虚拟列表 |

MP-Manager 自身编辑器未实现分块加载（其模块详解 §6.2 与 §11「可改进点」明确列出）；本项目实现的是该文档给出的目标方案，而非其现有实现。

## 2 实现

| 组件 | 位置 | 职责 |
|---|---|---|
| `SparseLineIndex` | `data/SparseLineIndex.kt` | 单次扫描，仅存每 `GRANULARITY = 1024` 行的字节起始偏移 |
| `ChunkedDocument` | 同上 | 256KB 块、16 块 LRU，缓存**原始字节** |
| `IndexedLineProvider` | 同上 | 从最近索引点按块读取、整段解码后切出目标行；`peek` 恒 null（无行缓存） |
| `FileSizeClass` | `data/FileSizeClass.kt` | 体积四档（5 / 50 / 200 MB），HUGE 只读预览并禁编辑 |
| `IndexedChunkedView` / `ChunkedInfoBar` | `ui/components/TextEditorDialog.kt` | `LazyColumn` 虚拟滚动；状态与档位提示 |

内存为 O(行数 / 1024) + O(窗口)，与文件体积无关。`ByteRangeReader` 为 IO 抽象：生产走 `ChunkedFileReaderAdapter`（ROOT / 非 ROOT 双路径），单测注入内存实现，JVM 可跑（不依赖 `RootService` / `android.jar`）。

## 3 与 MP-Manager 的差异

| 事项 | MP-Manager | shso | 原因 |
|---|---|---|---|
| 编码 | 仅 UTF-8（`toString(Charsets.UTF_8)`） | UTF-8 + UTF-16 检测（2 字节 LF 扫描） | 需打开 UTF-16 文本 |
| 块缓存对象 | 解码后字符串 | 原始字节 | UTF-16 跨块不截断多字节字符 |
| 块缓存实现 | `android.util.LruCache` | `java.util.LinkedHashMap(accessOrder)` 16 块 | 保持 JVM 单测可跑；容量按块数计（`指南` §9.2 的 `sizeOf = value.length` 会使总量仅 16 字符，取 §7.2 原意） |
| 只读阈值 | SMALL < 5MB 全量可编辑 | > 128KB 即只读优先（`LARGE_FILE_THRESHOLD`） | 编辑器 > 6.4 万字符走原生 `EditText`，全量排版 512KB 实测阻塞约 2.6 秒 |
| 渲染容器 | RecyclerView（§9.3） | Compose `LazyColumn` | 工程为 Compose |
| 索引粒度 | §4.3 稀疏 1024；§7.3 另给全量 `LongArray` | 稀疏 1024 | 全量按 8B/行，1 亿行需约 800MB；稀疏恒为 O(行数 / 1024) |

## 4 未采纳项

| 项 | 来源 | 原因 |
|---|---|---|
| 编辑时只回写改动块 | 可行性 §14.3 | 编辑态走全文 `contentValue`；超过 32MB 直接禁编辑 |
| 分块搜索 | 可行性 §14.2 | 只读态未载入全文，查找入口已拦截并提示先「编辑」 |
| `@Serializable` 会话 / 多标签快照 | 可行性 §8.6 | shso 为单文件对话框，无多标签会话模型 |
| Sora 视口喂行 | 可行性 §7.4 方案 1 | 无 Sora 依赖；`LazyColumn` 即该校 §7.4 方案 2 |
| `DocumentSource` 多源抽象（file / SAF / zip / FTP） | 可行性 §6.2① | 编辑器只处理本地文件；`ByteRangeReader` 已覆盖所需 IO |
